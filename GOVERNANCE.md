# Governance

The owner appoints the initial lead maintainer and publishes that identity before release. This repository does not invent maintainers, an institutional affiliation, a committee or an OpenMMLab endorsement.

Small implementation fixes use normal review. Public protocol/schema changes, new task semantics, benchmark identity rules and execution/trust-boundary changes require an RFC. Every breaking artifact change needs a reader or an explicit migration plan.

New maintainers are added by the existing maintainers after documented contribution and review experience. Security reports use the approved private route in PUBLICATION.json. Disagreements are recorded with the decision and rationale; evidence can contradict prior expectations without being removed.

Alpha native integrations remain provisional until their named environment is exercised. A maintainer cannot promote a scientific reproduction level merely by editing a badge.
